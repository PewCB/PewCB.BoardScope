# BoardScope MVP

A local Windows PCB microscope scanner. C#/.NET 10 controls the UVC camera and FluidNC; the browser provides the capture workspace and a tiled OpenSeadragon viewer. Capture, stitching and viewing run locally in the app.

## Run

Double-click **Start BoardScope.cmd**, or run `powershell -ExecutionPolicy Bypass -File .\start.ps1` from this folder. Open **http://127.0.0.1:5274/**. The launcher builds the app if it is not already running. It requires the .NET 10 SDK on Windows x64. NuGet packages are restored during the first build; OpenSeadragon and its license are included in the source tree.

## Development and source control

Run `powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1` for the native synthetic checks and all JavaScript checks. These require the .NET 10 SDK and Node.js, generate synthetic images in temporary folders, and do not require camera or stage hardware.

Source control includes application code, tests, launch scripts, third-party notices, SVG interface assets and stage configuration. `configs/fluidnc/config.yaml` describes this stage's wiring and travel settings; adapt it to your hardware before use. `STALLGUARD.md` and `stallguard-x-test.yaml` retain the stage's calibration history and an older test configuration. Controller dumps and workstation-specific investigation notes remain local. `tools/CoordinateConversion` is a historical migration utility for specific legacy datasets, not a setup step.

The `data/` folder holds local captures, saved projects, defaults and lighting references. Set `BOARDSCOPE_DATA` to use another data directory. Image data, image pyramids, exports in `output/`, build output, logs, local environment files and editor state are ignored by Git. Raster images are also ignored outside the data directory; keep new scan data out of source control. Local data is not backed up by Git and needs its own backup.

The camera and serial port are opened explicitly from the UI; starting the service alone does not move the stage. Close other programs that own the camera or the selected COM port. The serial connection asserts DTR, which native USB CDC on the ESP32-S3 needs for console/status responses, and leaves RTS deasserted. Opening USB serial can reboot an ESP32; the app waits for a fresh position report. It accepts an Idle controller after reconnecting; an app restart alone does not require another homing cycle. FluidNC owns its homing-required/alarm policy.

## Capture, scale and defaults

1. Select the UVC camera and capture mode, then open the camera. Modes and control ranges come from the Windows driver. Exposure is a Windows log-base-two value; its reported minimum, maximum, step and nominal time range are displayed beside the control. Auto exposure disables manual adjustment.
2. Connect the FluidNC serial port, normally at 115200 baud. Match the controller status units if FluidNC reports inches. **Home stage** runs the controller's configured `$H` homing cycle and displays progress. In **Moving platform → Board center coordinates**, save the board center in machine millimetres (initially X100, Y60). **Move to board center**, beside Home, moves directly to that saved destination. Absolute center moves and scans require a connected, Idle controller. Homing performed before opening the app remains usable when FluidNC is still ready. **Stop homing** sends a controller reset; reconnect and home afterward.
3. Use **Calibrate frame size & angle → Measure automatically**. Choose Image X+ or X−. The app takes a native-resolution phase-correlation pair with a measured 0.5 mm move, then uses its scale and angle estimate for another pair with about 50% horizontal overlap. Both pairs use phase correlation with illumination removal, overlap refinement and checks that different overlap regions agree on a single translation. The first search is zero-padded to prevent half-frame wraparound; the second searches the overlap predicted by the initial measurement. Results report phase response, aligned correlation and region agreement. Both pairs take up slack using the configured row-start approach distance, wait for settling and capture fresh frames at Idle positions. The second pair is shown as two original PNGs placed at the measured offset. Switch **1 on top / 2 on top**, or enable **Blink**, and inspect the overlap at **1:1**. Check the visual confirmation and press **Approve frame size & angle** to apply the refined frame dimensions and stage-to-image angle. No change is applied before approval; save defaults explicitly afterward. The job can be stopped, respects travel bounds, and rejects weak matches, camera movement/magnification changes and inconsistent estimates. One-axis calibration assumes square pixels and the configured axis handedness; it does not measure X/Y skew. Keep magnification unchanged until approval.

   **Manual feature calibration** remains available inside the same panel: take two snapshots around a known jog, place and confirm the same crosshair feature, and use the calculated frame width. This fallback sends no movement itself.
4. Jog X/Y buttons follow the configured axis signs and swap settings. Jog X+ means right and Y+ means up; scan columns go right and rows go down, so row movement uses the opposite direction to jog Y+. Their tooltips show the actual stage displacement. Machine position remains raw controller coordinates. Datasets record this Y convention and use its inverse for image placement.
5. Set the scan width and height, then use **Scan board coverage**. The scan rectangle is centered on the saved board center. Optional offsets in **Scan position relative to board center** shift it right/down in the image using the configured axis mapping. No manual reference marking is needed. The grid shows coverage, captured count and the next tile. All rows capture left to right with a preload at the start.
6. Inspect separate tiles by hovering over the mosaic. Hover isolates that tile and displays its recorded coordinates. The captured-tile sidebar list has been removed; the sidebar contains mosaic settings and saved projects.
7. **Save current settings as defaults** persists scan, axis, camera mode/controls, serial, jog and platform-center preferences to `data/defaults.json`. **Save center** saves just the platform center while preserving other defaults. Saved defaults load on page startup. Devices still open explicitly, and camera controls are restored when opening the saved camera. Homing status and live machine position are session data.

With the live camera and stage connected, drag the image to pan the PCB view. Distance follows the calibrated frame width and configured axis signs/swap, independently of the jog-button step. Moves run one at a time in short segments; Escape, leaving the live tab or losing pointer focus discards pending movement. An already-issued segment finishes. Dragging is disabled during automatic jobs and other hardware actions. Live rotation and mirroring match the saved captures.

The capture grid uses a larger scrollable canvas with row/column labels, a captured count and an explicit next-tile indicator. **View scan progress**, or the mosaic tab during collection, shows the whole board filling with small JPEG previews at measured stage positions. Each capture adds one preview, preserving zoom/pan. Yellow outlines show the next planned capture and a blue dashed outline shows the current stage view. Progress viewing does not register, blend or build pyramids; the existing **Stitch when capture finishes** setting still controls the final mosaic.

## Automatic scan

Home the stage and configure the saved platform center, scan dimensions, calibrated field of view, axis mapping and feed. The app positions the scan rectangle relative to the platform center and starts at its top-left tile. Offsets use image directions (X right, Y down); the platform center itself always uses raw machine coordinates. Travel limits are measured from the saved board center and include offsets and row-start approach moves. **Scan board coverage** moves to frame centres, confirms a fresh Idle/position report, waits for settling, then discards a configurable number of incoming frames before saving. Each new dataset records the platform center and computed scan center. Existing datasets retain their recorded center/corner conventions for viewing and restitching.

Every row captures left to right in the oriented image, following the configured axis signs and swap. Before each row, including the first, the stage moves to a point before column 1 and then advances to its capture position in the same direction as subsequent tiles. No images are taken during the return or approach. **Row-start approach · mm**, under Orientation & automatic motion, defaults to 0.5 mm; set it above the measured mechanical play. Zero disables the extra approach move. Both capture and approach positions must fit the configured travel envelope. This reduces backlash caused by alternating X travel, at the cost of a return move on every row.

The saved board center survives app restarts. BoardScope checks fresh controller positions and Idle status, and does not impose a separate per-app-session homing requirement. FluidNC controls whether homing is required after a reset or alarm. App travel bounds extend from the saved board center in either direction; they do not discover physical end stops. **Stop after current move** stops scheduling scan, calibration or center moves, lets the accepted move finish, and waits for Idle before releasing the job. It preserves saved captures and machine coordinates; normal stopping needs no reset or rehoming. The red jog stop also clears pending image-pan moves and lets the current move finish. **Stop homing** remains an explicit controller reset. The app never automatically unlocks or resumes a held controller.

## Shared calibration restitching

**Restitch with hybrid matching** is available on each saved scan and in Mosaic settings. It tries each overlapping pair independently: phase correlation, NCC, both with alternate illumination preprocessing if needed, then SIFT with configured sensitivity, a more sensitive detector, and finally faint-detail detection with local contrast at full resolution. It stops at the first accepted method, with at most seven distinct attempts. Feature caches are loaded only when pixel methods fail. Retries retain your mechanical limits and phase/NCC confidence thresholds; they do not lower the existing geometric, RANSAC or feature-distribution acceptance checks.

All accepted pixel translations and feature observations enter the same global shared-calibration/tile-position solve. The existing global consistency pass can still discard locally accepted outliers. Unmatchable pairs stay rejected. Hybrid creates its own saved stitch and map; older maps and source captures remain available. Choose **Hybrid** under **Default method after scan**, then save defaults, to use it for future captures.

Hover/select a pair in Match diagnostics to see the actual successful method and its scores/features. **Hybrid attempts** lists every attempted configuration, acceptance and rejection reason; “pair matched” describes the local result, while the main neighbor status also reflects global consistency. **Try hybrid matching on this pair** previews the cascade on older datasets without changing their saved neighbor graph or placement. On a hybrid dataset, the current-settings preview runs the hybrid cascade again.

In the project library, choose **Restitch with refinement** to register an existing dataset. No camera or stage connection is needed, and the action sends no motion commands. Open **Inspect tiles** to adjust **Shared calibration refinement**: per-tile mechanical displacement (mm), shared stage angle correction (degrees), shared pixels/mm correction (%), and matching resolution. Defaults are 0.25 mm, 3°, 3%, and full original resolution with 6000 SIFT features per tile. The mechanical displacement limit applies after the shared calibration correction; the total centre displacement can be larger on a wide board.

The fixed camera has one magnification and angle throughout a scan. Captured image pixels therefore retain their original scale and orientation; each image can only translate. The registrar caches SIFT features and finds mutual matches in predicted overlaps. A RANSAC affine fit rejects outliers and pairs with incompatible magnification/orientation, then a translation check retains consistent observations. Every retained feature pair across every accepted overlap enters one joint least-squares system: two shared stage-mapping variables and an X/Y mechanical offset per tile. Textured regions are balanced by weight instead of truncating observations. Robust passes re-solve the full system to reduce bad-match influence, and a second solve can reject globally inconsistent pairs. Soft priors favor small mechanical offsets, assigning systematic errors to the shared calibration. Tile 1 participates, tile order does not select an anchor, and unsupported tiles use the shared calibration with zero mechanical offset. Raw stage coordinates and originals remain intact.

After completion, **Individual tiles → Refined positions** shows translated source images without blending; **Stage positions** provides the baseline. **Stitched mosaic** shows the refined blend; **Original stage mosaic** opens the previous version. Hover isolates tiles and shows total centre displacement, mechanical offset, neighbor support and alignment error. The inspector reports the shared angle and pixels/mm correction, implied frame width, supported tiles and rejected pairs, with a versioned JSON report. Refinement does not change capture defaults or issue hardware commands. Existing saved refinements remain viewable; another refined restitch applies this new model.

**Match diagnostics** in the mosaic settings helps inspect weakly supported tiles. In **Individual tiles**, hover to show accepted neighbors with green outlines/connections and rejected neighbors with red dashed outlines/connections. Red tile edges mark zero accepted neighbors and amber marks one; the panel also counts disconnected groups in the accepted-match graph. The hover card lists neighbor numbers. Hover an overlap to load native feature coordinates for that pair: cyan circles belong to the first tile, amber crosses to the second, with line segments showing disagreement in the currently displayed layout. Retained pairs are green and excluded observations are red. Toggle excluded matches or all detected features in the search region to diagnose feature scarcity, descriptor rejection, stage gates or RANSAC rejection.

Click a tile to pin it, then choose a checked neighbor in the panel, including rejected pairs that no longer overlap in the displayed layout. **Fit pair** zooms to both images; the two **on top** buttons switch the visible image to check alignment. Escape or **Unpin tile** clears the pin. The panel shows the original pair acceptance/reason, match/inlier counts, pair-fit error, solved error when available, and detected-feature counts. New restitches save versioned per-pair coordinates, loaded lazily. Older scans reconstruct coordinates from saved images/SIFT caches on first inspection and cache them separately; their original report, placement, images and mosaic stay unchanged. Reconstructed observations follow current matching rules and are explicitly labeled, with the recheck result shown separately from the saved neighbor acceptance. **Reload features** retries a failed request. Feature inspection never issues motion commands.

For faint dust/specks on otherwise empty PCB areas, open **Shared calibration refinement → Feature detection sensitivity**. SIFT contrast presets are **Normal (0.04)**, **Sensitive (0.01)** and **Very sensitive (0.003)**; an editable threshold supports 0.0001–0.2, with lower values detecting weaker contrast. The feature limit per tile is adjustable from 500 to 20,000 (default 6000). **Enhance local contrast for detection** applies CLAHE to the matching grayscale image only; original captures and rendered mosaic pixels remain untouched. Keep full resolution to retain tiny details. These controls apply to the next refined restitch, and its report saves the actual options. Normal sensitivity without enhancement preserves the legacy detector behavior and caches; changed detector options get separate caches.

Select a pair under **Match diagnostics**, then press **Try current detection settings** to recheck that pair with the current refinement controls. It pins the pair, shows the new feature count and acceptance/rejection result, and colors retained preview matches accordingly. Saved neighbor support, positions, reports and mosaic stay unchanged; apply promising settings with **Restitch with refinement**. The preview still uses all existing correspondence, geometric and distribution checks. Its result is explicitly labeled **PREVIEW ONLY** and records the detector settings used; **Reload features** returns to the saved/reconstructed observations. Feature caches can be generated on first use, but previews never capture images or move the stage.

Refinement changes the shared conversion of stage-derived centres, rather than rotating/resizing individual tile contents. Shared calibration and arbitrary offsets are mathematically ambiguous without priors: the preference for small mechanical offsets selects the common systematic correction. The model assumes square pixels and stable camera magnification/orientation; it does not estimate X/Y skew, perspective, lens distortion or local deformation. Fine detail can still mismatch around raised components. Feature coordinates come from the selected matching resolution, and rendering uses full-resolution originals in bounded output regions.

## Saved projects and viewing

### Alternative restitch: phase correlation

Open an existing scan and press **Restitch with phase correlation**, either on its library card or under **Shared calibration refinement**. The separate **Restitch with feature matching** button retains the SIFT method. Both start from the recorded stage layout and use the same shared scale/angle and mechanical shift limits; matching resolution defaults to full source resolution. Existing datasets need no conversion or recapture.

Phase correlation uses the grayscale pixels in each stage-predicted overlap, with a Hann window and optional subtraction of smooth illumination. It estimates a subpixel translation rather than detecting descriptors. The default gates are minimum phase response **0.15** and minimum normalized correlation after shifting **0.30**; both are editable under **Phase correlation settings**. Response is a match score, not a probability. Flat overlaps, offsets outside the stage tolerance, near-wraparound offsets and poorly correlated pairs are rejected. Reliable translations enter the existing robust whole-board solve together, with one shared stage scale/angle and individual mechanical offsets. Source pixels keep their original scale/orientation. Inconsistent global constraints are rejected and the layout is solved again. Periodic textures or differences around raised components can still produce ambiguous matches; use pair inspection to assess results.

In **Individual tiles → Match diagnostics**, phase pairs show response, aligned correlation, measured relative placement, correction from the stage estimate and solved residual. The overlay shows a labeled translation constraint, rather than invented feature points. **Try phase correlation on this pair** also works on a previously rejected SIFT overlap: it previews a single pair without changing saved alignment or acceptance. For a phase-restitch result, that button becomes **Try feature matching on this pair**. The settings preview uses the saved method; **Reload features** restores the saved diagnostics.

Each successful restitch retains prior alignments and their rendered maps in **Stitches & maps**. A failed restitch preserves the completed saved mosaic and project metadata. Captures and raw recorded coordinates remain unchanged. Phase checks use temporary synthetic datasets, not the project library or hardware.

### Alternative restitch: normalized cross-correlation (NCC)

**Restitch with NCC** is a third independent method, available on saved-scan cards and under **Shared calibration refinement**. It searches translations around the stage estimate using zero-mean normalized pixel correlation (`TM_CCOEFF_NORMED`), fits the peak for a subpixel offset, and checks the actual interpolated patch correlation. Accepted translations enter the same joint stage scale/angle and mechanical-offset solve as phase correlation. Originals are rendered at full resolution; matching uses the selected **Matching resolution**. Older scans work without conversion.

Under **Normalized cross-correlation settings**, the default minimum correlation is **0.50**, with smooth illumination removal enabled. **Optional competing-peak gap** defaults to **0**, so competing peaks do not reject pairs by default. A positive value enables that additional check; the second peak is measured outside a neighborhood of approximately five source pixels (at least three matching pixels) around the best peak. Diagnostics distinguish the integer peak score, correlation after subpixel alignment, second peak and peak gap; scores are not probabilities.

The fixed overlap template and search area stay inside real source pixels. Search is bounded by the mechanical shift and shared calibration limits, and narrowed further when the overlap strip is too small. Templates require at least 48 matching pixels in each dimension, plus borders and search margin. Flat templates, weak correlations and peaks at the rectangular or circular search boundary are rejected. Boundary rejection prevents accepting a truncated, out-of-range shift; check overlap and correction limits if this occurs. **Match diagnostics → Try NCC on this pair** previews NCC on a saved SIFT or phase pair without changing saved alignment or neighbor acceptance. On an NCC-refined scan, the preview controls also offer SIFT and phase correlation for comparison.

Synthetic native and frontend checks cover NCC offsets, faint texture, brightness changes, bounded search, optional peak rejection, joint layout solving, saved diagnostics and older-dataset previews.

### Stitches and rendered maps

The selected project's **Stitches & maps** list shows each saved method and date/time. **Inspect tiles** opens that stitch's exact saved positions and pair diagnostics; tile number labels appear only under the pointer. Each stitch owns its rendered maps, listed by date/time, seam method and dimensions. **Load map** displays a chosen map, and the workspace heading identifies the stitch and map currently viewed. Loading an older result is read-only and does not replace the latest saved result.

Switching between individual tiles and rendered maps preserves the visible board region and pixel zoom, accounting for each view's coordinate scale and crop origin. Opening another board fits that board initially; **Fit** remains available to reset the view explicitly.

**Save map viewer HTML** exports the selected saved map as a static viewer with OpenSeadragon, styling, pyramid metadata and its license embedded. Choose the filename and predefined `.dzi` address. The default is an absolute `file:///` address to the map on disk: open the saved HTML locally to view it, even after closing BoardScope. Images stay in their existing `_files` folder and are loaded on demand. No backend, external script or CDN is needed by the exported viewer.

**Save GitHub Pages board** is an alternative export for a local static-site repository. Its default parent is `C:\exo\PewCB.GigaPixelScans`. Enter the board/folder name (for example `CoreXY`), public page URL and description. It writes `CoreXY/index.html`, the selected map's `.dzi` and matching `_files` folder, `preview.jpg` (1200×630), and `thumbnail.jpg` (512×512). Tile links are `./mosaic-<version>.dzi`; OpenSeadragon and the supplied PewCB SVG favicon are embedded. The page includes a branded title, description, canonical URL, Open Graph/X image tags, and a static image fallback when JavaScript is disabled. Canonical and social-image URLs use the public address entered in the dialog. Nothing is pushed or published automatically.

Existing board folders are refused unless **Replace existing board folder, keeping a backup** is selected. Export is staged before publication; replacement retains the entire former folder as a hidden sibling backup and reports its path. Captures, saved alignments and map files in the project library remain unchanged. Capturing/stitching must finish before copying an export.

Each board folder also gets `README.md` with the entered description and a direct public viewer link. The parent repository's main `README.md` contains a complete scan index linking to every board README and public page. This generated section is refreshed on export; existing introduction/footer text is preserved, and hidden backups are excluded. Older exports supply their URLs and descriptions through the HTML metadata. To add missing board READMEs and refresh the index once, run `dotnet run --project tests/BoardScope.Checks -c Release -- --pages-readmes C:\exo\PewCB.GigaPixelScans`. Existing board READMEs are preserved by this backfill.

Relative paths also work: enter `./mosaic-<version>.dzi` when the HTML is beside the pyramid, or `../scan/mosaic-<version>.dzi` when it is one folder below. They resolve relative to the saved HTML, rather than the BoardScope app, so moving the HTML and pyramid together preserves the links. Keep the matching `_files` folder beside the descriptor. Use the exact filename of the map being exported.

For static hosting, upload the tile pyramid and enter its HTTPS `.dzi` address or a relative path at export time, or change `mosaicUrl` in the saved HTML later. The embedded dimensions describe this particular map; export again for a different map. The viewer loads visible tiles first, retains a bounded cache, then prefetches a one-tile border and up to four center tiles at the next zoom level. It allows at most two background downloads and holds at most 32 completed prefetched images, with a separate 128-tile viewer cache. Panning replaces queued background work; decoded prefetched images are reused directly when needed. The full board is never preloaded at full resolution.

Choose a seam method and use **Add blended map** to render another map from that stitch's immutable alignment. **Reblend current alignment** does the same for the alignment being viewed. Both preserve earlier maps. Deleting a map removes its pyramid from disk but keeps its alignment; deleting a stitch removes its alignment, diagnostics and all its maps. Original captures and other stitches remain available. After deleting the current saved result, the project falls back to another available map or alignment.

Existing projects are indexed once when opened while no job is running. The current alignment and map are preserved together. Older reports with exact tile transforms become inspectable alignments that can be reblended. Older maps without a recorded association to those transforms are retained as map-only entries; tile inspection and reblending are unavailable for those entries. Recovered report alignments use full image bounds because the old crop configuration was not recorded.

Under scan settings, **Default method after scan** chooses stage positions, feature matching, phase correlation or NCC for automatic stitching. **Default map seams after scan** chooses its blend. Use **Save current settings as defaults** to persist both choices. Refinement uses standard matching settings unless custom options were saved through the API.

Each saved-project card shows a small board preview from its mosaic. Unstitched projects use a cached thumbnail of their first capture. Click the pencil beside a card name or the selected workspace title to rename it. Names are saved in project metadata; captured images, positions, alignment and mosaic versions stay unchanged. **Delete** on a project card permanently removes its entire project folder, including captures, all mosaic versions, source pyramids, previews, registration caches and metadata. A confirmation names the scan being removed. Capture/stitching or manual collection must finish first. Deleting the selected scan clears its viewer, and deleting the final scan restores the empty library. Other projects and app defaults remain in place.

Projects are stored in `data/<project-id>/`:

- `captures/`: normalized, full-resolution PNG frames. If the camera streams MJPEG, these preserve the decoded pixels without an additional JPEG save; they cannot undo camera compression.
- `project.json`: camera parameters, calibration, reference, timestamps, measured positions, and job state. Written after each capture.
- `stitches/<id>/alignment.json`: immutable tile positions, transforms, diagnostics reference and calibration for each saved stitch. The project catalog links each stitch to its own rendered maps.
- `positions.csv`: measured stage and nominal pixel positions.
- `tile-views/`: independent image pyramids for inspecting individual source tiles.
- `registration-cache/`: reusable image features, separate from source captures.
- `registration-<version>.json`: pair acceptance diagnostics, shared stage calibration and per-tile translation/mechanical offsets (older reports can contain per-tile similarities).
- `registration-<version>-debug/pair-<first>-<second>.json`: versioned feature observations or phase correlation measurements for each checked pair, including rejected pairs; indices in files are zero-based, while the UI uses tile numbers starting at 1.
- `match-debug-cache/`: lazily reconstructed pair observations for older scans.
- `mosaic-<version>.dzi` and its `_files/` folder: the viewing pyramid.

The stitcher converts recorded movement into pixels using the explicitly entered frame width, aspect-derived height, signs and axis mapping. It preserves original stage coordinates and initial estimates. Manual/test/imported mosaics include the union of all placed tile bounds, including negative coordinates; board-coverage scans retain their configured crop. It feather-blends in bounded 512-pixel regions with a bounded source cache, without allocating the entire mosaic as one bitmap. Both stitched and individual-image viewers request visible tiles and mip levels on demand. Pyramid tiles are JPEG; original captures remain PNG. Refinement starts from this stage layout and constrains visual corrections around it. Verify frame width and axis mapping before refinement.

New pyramids use new filenames. A failed rebuild does not replace a previously working mosaic. Partial captures remain available for restitching. Scan continuation after a controller reset is intentionally not automatic.

The tile inspector's **Mosaic seams** selector controls the next rebuild. **Sharp seams** assigns each covered pixel to the nearest transformed tile center. This creates straight Voronoi boundaries and uses only that tile's pixels, with no mixing across overlapping captures. **Feathered seams** retains the previous weighted overlap blending. On opening a map, the seam selector reflects its saved blend; choose another blend before reblending. Automatic scan stitching uses its separate configured seam preference. **Reblend current alignment** renders with the selected seam method while preserving all saved positions, rotations, scales and registration diagnostics. Restitching from stage or with refinement also uses the selected seam method. JPEG pyramid compression and interpolation within a rotated/scaled source still apply.

The three legacy datasets captured before the center/Y-up convention were converted once with `tools/CoordinateConversion`. The conversion retains their original top-left reference and every captured image, raw machine coordinate and initial pixel estimate; it changes the saved vertical axis sign and records `gridYSign = -1` so placement stays identical in the current app. The 943-tile dataset's original stage mosaic was verified against source patches and restored after an incompatible restitch. Original JSON/CSV metadata is backed up under `output/coordinate-conversion-<timestamp>/`. Each converted project has an audit marker; rerunning the conversion skips it. This utility targets those three inspected datasets and is not an automatic migration for arbitrary imports.

**Open large image** accepts a full local path to a supported image, including TIFF/BigTIFF, and uses NetVips to generate a DZI pyramid. **Import tile grid** accepts JPG/PNG/TIFF images sorted naturally by filename; choose row-major or snake order and supply the grid size and approximate overlap. The 2D import expects equal-sized tiles and does not import a multipage Z-stack.

## Validation and limits

Run `dotnet run --project tests/BoardScope.Checks -c Release` for the internal checks. They exercise scan bounds, row preloads, axis mapping, saved preferences, position-only placement, preserved raw coordinates, negative canvas bounds, aspect-derived height, image pyramids, shared calibration recovery, per-tile translations, loop constraints, outliers, tile-order invariance, correction limits, unsupported captures, cancellation and native SIFT matching without per-tile warping. Check data is written to a temporary folder rather than the project library. Add `-- --real data/<project-id>` to rebuild a real capture set in a temporary copy without modifying its originals.

Verified on this machine: a clean Release build, real UVC MJPEG preview at 1920×1080/30 FPS, COM4 startup/status handling, manual captures, and user-triggered automatic nine-tile collections. Current synthetic UI checks cover coordinate mapping, live previews and calibration review; hardware calibration is tested by the user.

Placement supports stage translations, shared stage scale/angle refinement and individual mechanical position corrections. Parallax-aware matching can select a consistent depth-surface translation, and content-aware sharp seams can reduce visible residual disagreement. Older per-tile similarities remain viewable. It does not reconstruct depth or correct lens distortion, perspective within a tile, local deformation, uneven illumination or focus variation. A single translation cannot align every height surface perfectly. Each imported source image is limited to 40 megapixels / 128 MB; scan grids to 10,000 captures; built-in mosaic output to 20 gigapixels. These are MVP limits, not measured performance guarantees. Large-image pyramid generation with libvips finishes its current native operation before observing cancellation.

## Parallax-aware strategy

**Restitch with parallax-aware matching** is a separate strategy available for existing captures and as a saved after-scan default. It samples up to nine overlapping regions per tile pair and tests phase correlation and NCC at native/selected, half and quarter resolution. Existing confidence and stage correction limits still apply. Different resolutions/methods from one region count as one vote. At least two independent regions must agree to form a local offset hypothesis. Confidence and displacement spread weight the resulting translation constraints.

Several coherent offsets are retained, rather than combining different apparent depths into one translation. After a first joint layout solve, ambiguous or inconsistent pairs are compared against a solve that excludes that pair, provided another graph path connects its endpoints. Poorly fitting hypotheses also trigger the full Hybrid method/settings cascade, retaining its alternative successful offsets. Two selection passes are followed by removal and re-solving of remaining inconsistent pairs; final accepted pairs are checked against the final layout. A bridge with no independent connecting path cannot receive global confirmation. Broadly wrong matches shared by many neighbors, or a board with no visible substrate texture, can still defeat this strategy.

Pair diagnostics show patch translations, alternative offset groups, confidence/spread, selected offset, final layout residuals, global comparisons and hypothesis switches. These arrows are measured patch shifts, not detected feature points. Pair previews are local only; a full restitch is required for global selection. Saved diagnostics preserve the actual selection and the original captures remain unchanged. Existing Hybrid/SIFT/phase/NCC strategies are unchanged.

Select **Content-aware sharp** under Mosaic seams to route cuts through areas with low image disagreement and low edge detail. This is also available when reblending any saved alignment. Costs are sampled at up to 512 pixels along each overlap's longest dimension; complete seam paths are computed once and reused across every output block. Rendering still uses one original full-resolution source per pixel, with no cross-image feathering and no local geometric warping. At junctions, the fewest violated pairwise cuts wins, with nearest-center tie breaking; all covered pixels retain a source. This is a bounded, pairwise seam heuristic, not component segmentation, and cannot guarantee an intact component or hide large parallax. Map history records this seam mode separately from straight sharp and feathered maps.

Run `dotnet run --project tests/BoardScope.Checks -c Release -- --parallax` for focused synthetic blur/depth-mode, independent-neighbor selection, saved-map/diagnostic, cancellation, blank-region and sharp rendering checks, without hardware or library changes.

## Mosaic image effects

Open a saved map and choose **Image effects…** under Stitches & maps. Brightness, contrast, shadows, highlights, saturation, temperature and tint range from −100 to 100, with 0 neutral. The small preview is calculated locally in a browser worker, coalescing rapid slider changes. **Show original** compares with its source. Preview the whole board or zoom the mosaic first and choose **Current view** to check a detail. Downsampled preview tones approximate full-resolution results; both paths use the same pixel transform and rounding.

**Apply to full mosaic** processes the selected map's full-resolution pyramid tiles with bounded parallel CPU work, then rebuilds every lower zoom level. It creates a separate **Image effects** map under the same stitch and switches to that map when finished. It does not repeat registration or seam calculation. Existing maps, alignment, stage coordinates and original captures are retained. Adjusted maps contain baked pixels, so static HTML and GitHub Pages exports need no special effect support.

Effect settings and their source-map ID are saved with each map. Reopening an adjusted map's effects starts from its original source, avoiding cumulative adjustments and JPEG generations. If that source map has been deleted, the adjusted map remains independently viewable and further adjustments begin from its baked image with neutral sliders. Resetting sliders while the source exists can remove previous effects. Applying non-neutral effects uses JPEG Q95 for new full-resolution pyramid tiles; original captures are never recompressed. Cancellation or a failed tile removes the incomplete new map and retains the previous result.

Run `dotnet run --project tests/BoardScope.Checks -c Release -- --effects` for focused native validation. `node tests/image-effects.cjs` checks worker behavior, slider coalescing, comparisons, saved-source handling, preview cancellation and map targeting; pass the native run's `effect-pixels.json` path as its first argument to compare browser and native pixel outputs byte for byte.

## Light background correction

Auto camera control values refresh from the driver while automatic mode is active. Unchecking Auto or choosing **Lock supported auto controls** reads each control again immediately before sending its reported value in manual mode. This avoids applying an old UI snapshot. Drivers may report a stored manual white-balance value rather than their internal automatic channel gains; check visually that locking preserves the result. The displayed number is the driver-reported value, not a measurement of its hidden gains.

Under **Microscope camera → Lighting correction**, fill the camera frame with a clean, diffuse white surface at the scan magnification and lighting. Lock automatic exposure, gain and white balance using **Lock supported auto controls**. Avoid overexposure, then press **Capture light background**. BoardScope averages eight fresh frames, saves a lossless reference PNG, and robustly fits a separate total-degree-four polynomial (15 coefficients, including cross terms) for each color channel on normalized sensor coordinates. Clipped, dark, nonpositive or excessively varying references are rejected. **Inspect reference & fit** shows the capture, the analytical surface and the corrected reference; the residual and gain range help assess the fit.

For channel `c`, source pixels are multiplied by `mean(surface_c) / surface_c(x,y)` before alignment, seam selection and full-resolution mosaic rendering. Each channel keeps its average level, preserving the overall color balance. The correction follows the saved camera rotation and mirrors. The **Correct lighting before stitching** switch persists across restarts; capturing a valid reference enables it. Re-capture after changing magnification, lighting or optics. A mismatching frame size or camera is rejected rather than silently applying another setup's calibration.

The active calibration applies to subsequent stitches and **Add blended map** operations. To correct an existing dataset without changing its alignment, open its saved stitch and add a blended map. Captures are never changed, and each map records its calibration independently. Corrected source tile pyramids and feature caches use separate calibration-specific paths; earlier maps continue to show their original tiles after replacing or disabling the reference. Image effects and static exports preserve the corrected pixels. Captures and fitted models live under `data/light-backgrounds/<id>/`; `data/light-background.json` stores the active profile and enable switch.

Run `dotnet run --project tests/BoardScope.Checks -c Release -- --light-background` for synthetic fit, rotation/mirror, per-channel color, reblend, history, persistence and rejection checks. `node tests/light-background.cjs` checks the controls, busy states and preview selection.
